# Portfolio repository instructions

When creating, modifying, reviewing, or refactoring frontend UI, use the `portfolio-design-system` skill located at:

`.agents/skills/portfolio-design-system/SKILL.md`

## Core rules

- Do not invent new colors, typography sizes, spacing values, grid rules, or visual patterns when an existing token or pattern can be used.
- Prefer reusable components over one-off styling.
- Use design tokens rather than hard-coded repeated values.
- Maintain the visual direction: contemporary editorial product-design portfolio with subtle Bauhaus influence.
- Keep project case studies readable, evidence-led, and story-driven.
- Preserve the visual identity of project screenshots and artifacts.
- Avoid decorative Bauhaus pastiche.
- Make responsive behavior intentional.
- Maintain accessibility and reduced-motion support.

If a requirement genuinely needs a new design-system value, add and document that value rather than introducing an unexplained exception.
